# Идея проекта

## Что это

**MLT Облік** — внутренняя система сервисного центра по ремонту техники. Сервис уже ведёт заявки в **RO App**, но RO App не позволяет удобно считать затраты на каждый ремонт. MLT Облік читает заявки из RO App по API и ведёт собственный учёт: закупки, склад по партиям, вложения материалов в заявки. Результат: достоверная **себестоимость каждого ремонта** и прозрачное движение денег и запчастей. Любая сумма должна прослеживаться до операции, закупки, позиции или заявки.

Чем система **не** является: она не заменяет RO App и не управляет ремонтами. В RO App ничего не пишется обратно. В будущем может вырасти в самостоятельную CRM, поэтому архитектура должна быть расширяемой, но в v1 это не делаем.

## Как идёт работа

1. Свели три источника: ТЗ клиента (результат его общения с ИИ), дизайн-промпт, краткое описание разработчика. Противоречия закрыли решениями, они зафиксированы в `02-spec.md`.
2. Собрали единое ТЗ.
3. Сделали фронтенд-прототип на моках (`client/`): всё работает на localStorage, бизнес-логика в `client/src/domain`.
4. Сейчас: уточняем фронт по замечаниям и готовим серверную часть. **Сервер разработчик пишет сам**, роль Claude здесь планирование, объяснение и ревью, кодить по запросу.

## Принятые решения (кратко)

| Тема | Решение |
|---|---|
| Стек | Фронт: React, Vite, TypeScript, Tailwind, shadcn-стиль. Бэк: NestJS, PostgreSQL, Prisma, REST, модульный монолит |
| Аутентификация | JWT, права проверяются только на сервере |
| RO App | Только чтение. Заявки, клиенты, техника; статусы и типы из справочников RO App с маппингом в локальные enum |
| Обновление из RO App | Три способа: вебхуки, кнопка глобального обновления, ночной автозапуск. Одна логика, без дублей, журнал IntegrationLog |
| Роли MVP | Администратор и исполнитель. Менеджерские права админ выдаёт каждому индивидуально |
| Цена вложения | Только FIFO. Вручную цена вводится лишь при создании закупки |
| Закрытые заявки | Правит только уполномоченный (`allocations.edit_closed`), причина обязательна, всё в журнал |
| Аналитика | Только себестоимость. Маржа и сравнение с суммой клиента не нужны |
| Доп. расходы | В v1 нет, но фундамент закладывается (сущность Expense, FinanceModule) |
| Валюта и деньги | UAH. На сервере Decimal, в клиентских моках целые копейки |
| Язык | Документация русская, интерфейс украинский |

## Решения, принятые после ТЗ v1

- **«Нераспределённое» = «на складе».** Это одно и то же. Отдельную страницу «Нерозподілені закупівлі» удалили, в строке товара на складе есть кнопка «Розподілити». Цена и стоимость остатка существуют в одном экземпляре.
- **Закупка по умолчанию идёт на склад.** Выбора назначения на странице «Нова закупівля» нет. «Закупка прямо в заявку» создаётся только из диалога вложения внутри заявки.
- **Палитра** из шести цветов (`#06141B #11212D #253745 #4A5C6A #9BA8AB #CCD0CF`), по умолчанию тёмная тема.
- **Фронтенд без CLI shadcn.** Компоненты `components/ui` написаны вручную в стиле shadcn, без Radix.
- **Мобильный дизайн** разработчика не устраивает, его будем переделывать. Правки фронта вернёмся делать позже.
