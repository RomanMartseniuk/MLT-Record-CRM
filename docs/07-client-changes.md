# Список правок клиента

Сюда записываем всё, что нужно поменять в `client/` из-за решений по серверу и ТЗ. Клиент не трогаем, пока разработчик не попросит. Когда пункт сделан, ставим `[x]` и дату.

Источники: `docs/02-spec.md` (журнал изменений), `docs/06-server-status.md`, схема `server/prisma/schema.prisma`.

## 1. Вложение-услуга (ТЗ 4.3, решение 2026-11-18)

Правила: название и сумма вручную, комментарий. Без подрядчика, без справочника. Перенос в другую заявку невозможен, только отмена. Правка названия и суммы возможна, причина необязательна. Склад, партии и FIFO не затрагиваются. Стоимость входит в себестоимость заявки.

- [ ] `api/contract/types.ts`: у `Allocation` необязательный `productId`, поле вида (`product` / `service`), `serviceName`, `comment`. У услуги нет строк (`AllocationLine`).
- [ ] `api/contract/dto/*`: входной DTO создания услуги и DTO правки (название, сумма, комментарий, причина необязательна); view model вложения заявки умеет показывать услугу.
- [ ] `api/contract/client.ts`: методы создания и правки услуги в sub-интерфейсе allocations.
- [ ] `api/mock/engine/allocations`: создание услуги без FIFO и без остатков; правка с записью в аудит (до и после); отмена; запрет переноса и возврата на склад для услуги.
- [ ] Права и закрытые заявки: создание, правка и отмена услуги в заявке «Видано» требуют `allocations.edit_closed`; причина в этом случае обязательна (как у товара).
- [ ] `api/mock/engine/reports`: себестоимость заявки, dashboard и аналитика включают услуги. Сверка склада с закупками услуги не учитывает.
- [ ] `invariants.test.ts` и тесты allocations: услуга не меняет остатки; сумма услуги входит в себестоимость; закрытая заявка; аудит.
- [ ] UI: диалог «Додати вкладення» получает вариант «Послуга/робота» (название, сумма, коментар). Строка услуги в карточке заявки, действия «Змінити» и «Скасувати» (без «Перенести» и «Повернути на склад»). Тексты на украинском.
- [ ] Журнал операций и фильтры: тип операции для услуги.
- [ ] Демо-данные (`seed/*`): хотя бы одна услуга в заявке.
- [ ] Обновить `client/README.md` (инварианты).

## 2. Пользователи

- [ ] `User.fullName` заменить на `firstName` и `lastName` (контракт, DTO, форма пользователя, шапка, журнал, демо-данные, везде где выводится имя).
- [ ] Пароль при создании пользователя генерирует сервер и один раз возвращает в ответе. Диалог создания показывает его (с кнопкой «скопировать»), поля ввода пароля нет.
- [ ] Сброс пароля админом: новый сгенерированный пароль показывается один раз.
- [ ] Смена пароля пользователем: форма и вызов `POST /auth/change-password`. Смена добровольная, принудительной нет.
- [ ] Вход: access JWT 8 ч и refresh-токен 30 дней; клиент обновляет токен при 401 и очищает сессию при выходе и блокировке.
